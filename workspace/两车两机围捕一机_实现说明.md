# 两车两机围捕一机：空中入侵无人机围捕任务实现说明

> 本文档整理 swarm_defense_ws 中"两车两机围捕一机"（空中入侵无人机围捕）的开发实现：系统组成、核心文件、状态机、关键算法与仿真运行方法。
>
> 任务：入侵无人机 **iris_2** 从外墙角出生 → 恒高飞越 3m 内墙 → 触发入侵警报 → 按 Voronoi 逃逸；防御方 **两辆 UGV（car0/car1）+ 两架 UAV（iris_0/iris_1）** 组成围捕阵型，将入侵机封锁于凸包内并逼近捕获条件，判定捕获（CAPTURED）或逃逸（ESCAPED）。
>
> 验证状态：固定出生角 CORNER_1（左下角）下全链路实测 **CAPTURED** 通过（双 UAV 均 < R_c=1.8、双 UGV < R_g=0.5、持续 2s）；围捕后全物体静止。

---

## 1. 系统组成与控制链路

```
                              ┌─────────────────────────────────────────────┐
                              │  air_intruder_pursuit.py（围捕 FSM 主节点）  │
                              │  WAITING→TAKEOFF→STAGING→INTRUDER_APPROACH→ │
                              │  AIR_INTRUSION_DETECTED→PURSUIT→ENCIRCLED   │
                              │  →CAPTURED / ESCAPED                         │
                              └──────┬──────────────────────┬───────────────┘
                                     │                      │
              UAV 目标（世界→局部系换算）│                      │ UGV 目标（世界系）
                                     ▼                      ▼
                 /iris_N/move_base_simple/goal     /carN/move_base_simple/goal
                                     │                      │
                             ego_planner_node               │
                              (EGO-Swarm 规划)               │  car3_control 的
                                     │                      │  nav_to_pose_node
                              traj_server                   │
                                     ▼                      ▼
                /xtdrone/iris_N/cmd_pose_enu          (car3 nav_to_pose)
                                     │
                         multirotor_communication.py（XTDrone 通信桥）
                                     │  hold_yaw 固定朝向 + HOVER_LOCK
                                     ▼
                /iris_N/mavros/setpoint_raw/local（仅桥发布）→ PX4 → 电机
```

**坐标约定**：战术计算统一用 Gazebo 世界系 `/gazebo/model_states` 的 XY；UAV 目标经 `_publish_world_goal` 按该机 EKF 局部系与世界系的平移偏移换算后发给 EGO（轴方向与世界系一致）；UGV 目标直接用世界系。

**排障关键**：UAV 的唯一指令通道是通信桥发布的 `setpoint_raw/local`；EGO 的 traj_server 残留轨迹会经 `cmd_pose_enu` 覆盖 hover 目标，故"围捕后静止"依赖桥的 `HOVER_LOCK`（见 §4.6）。

## 3. 状态机（FSM）

```
WAITING ──就绪(auto_start)→ TAKEOFF ──三机达恒高→ STAGING
STAGING ──iris_2 到出生角→ INTRUDER_APPROACH
INTRUDER_APPROACH ──XY 越过内区边界+去抖0.3s→ AIR_INTRUSION_DETECTED
AIR_INTRUSION_DETECTED ──立即→ PURSUIT
PURSUIT ──四追捕者凸包包围 iris_2→ ENCIRCLED
        └─ iris_2 离开内区→ ESCAPED
ENCIRCLED ──包围满足 + uav_max<R_c + cars_max<R_g 持续 T_hold=2s→ CAPTURED
         └─ 丢失包围持续 encircle_fallback_delay=1.5s→ 回退 PURSUIT（重新门封堵）
         └─ iris_2 离开内区→ ESCAPED
```

- **就绪条件** `_ready()`：5 机 model_states 齐、3 UAV local pose + MAVROS `connected/armed/OFFBOARD` 齐、3 UAV EGO goal 订阅者在线（UGV Nav 订阅者缺失仅告警）。
- **STAGING**：防御 UAV 保持出生位，iris_2 飞往出生角待机。
- **INTRUDER_APPROACH** 三步走：`staging_align`（门洞中心线预对齐点）→ `staging_outside`（墙外待机点）→ `entry_inside`（墙内点）。第二步到达后须**真正停稳**（水平速度持续 < 0.1 m/s 且停留 ≥1.2s，`entry_speed_cap=6s` 强制推进）才发墙内目标，否则 EGO 重规划带横向动量偏出门洞撞门框。

## 4. 关键算法

### 4.1 入侵机逃逸：bounded Voronoi 元胞质心

iris_2 的逃逸目标 = 五智能体（2 车 + 2 UAV + iris_2）在**内区包围盒**内的 Voronoi 元胞质心（`bounded_voronoi_cell` + `polygon_centroid`），并收缩到边界内 0.1m。即逃向"离追捕者最远的内区区域"。

### 4.2 围捕阵型 `_compute_pursuit_goals`

以 iris_2 逃逸方向 `e` 为基准（优先当前速度方向，速度过低退化为元胞质心方向）：

- **PURSUIT（宽松阵型）**：两 UAV 在逃逸方向前方 `d_uf=1.5`、横向展开 `d_us=2.0`；两 UGV 在投影后方 `d_gf=1.2`、横向展开 `d_gs=2.0`。全部目标 clamp 在内区边界内 `uav_margin=0.8` / `ugv_margin=0.4`。
- **ENCIRCLED（紧阵型）**：两 UAV 收到 iris_2 前方 0.4m ± 横向 0.6m；两 UGV **直接贴 iris_2 地面投影两侧 ±0.3m**（用户要求捕获时小车收在入侵机正下方，与 R_g=0.5 匹配）。UAV 目标一律 clamp（H_f=1.33 < 3m 墙，禁止越墙封口）。

### 4.3 包围判定 `_encircled_check`

四追捕者的**凸包**包含 iris_2 且凸包面积 ≥ 0.5m²；iris_2 在凸包边界 `encircle_margin=0.3m` 内也算包围（防边界振荡清零计时）。

### 4.4 门封堵 gate_seal

iris_2 逼近某条内墙边界（距离 < 1.8m）且逃逸方向与边界外法向点积 ≥ 0.3 时，较远一架防御 UAV 调至 iris_2 与边界之间的"影子"位（沿指向边界方向推进 1.0m，**停在边界内 uav_margin=0.8m**，不压墙面）——挖掉正对侧的 Voronoi 元胞，把逃逸质心拉回内区并放慢。封堵侧承诺停留 `dwell=1.5s`，防堵头目标大跳变。

### 4.5 捕获判定

```
enc（凸包包围） AND uav_max ≤ R_c=1.8（两架 UAV 均距 iris_2 的 XY 距离）
             AND cars_max ≤ R_g=0.5（两辆 UGV 距 iris_2 地面投影）
持续 T_hold = 2.0s → CAPTURED
```

- `uav_max` 取**最远**一架 UAV 的距离（不是最近），即两架都必须到位。
- `cars_max` 取最远一辆 UGV，保证小车已在入侵机正下方。

### 4.6 围捕后全物体静止

捕获/逃逸后 `_halt_all()`：UAV 发 **HOVER_LOCK**（桥锁定当前位姿、忽略后续一切 pose/vel 命令，阻断 EGO 残留逃逸轨迹覆盖）+ 以当前世界位姿（含当前 z）为原地目标；小车停原地。实测捕获后各机零位移（UAV 仅 PX4 悬停 ±0.15m 抖动）。

### 4.7 全机固定朝向

桥订阅 `/gazebo/model_states`，捕获每机**出生世界 yaw**；`hold_yaw() = fixed_world_yaw + (current_yaw - cur_world_yaw)` 换算成局部 yaw 指令，抵消 EKF 局部系相对世界系的旋转漂移。`cmd_pose_enu/flu` 与 HOVER 一律用 hold_yaw。实测 iris_0/1 全程 0°、iris_2 全程 -90°（出生朝 DOWN 门）。

### 4.8 起飞修复（MPC_LAND_CRWL）

SITL 中 PX4 EKF 的 vz 噪声（~0.17–0.25 m/s）在 ARM 时刻会超过地检垂向运动阈值 0.225 m/s（默认 `MPC_LAND_CRWL=0.5`），误清除 `landed` → 起飞斜坡永不启动 → `not_taken_off` 分支命令 0 推力、飞机不起飞。修复：起飞脚本在 OFFBOARD/ARM **前**经 mavros `param/set` 把 `MPC_LAND_CRWL=2.0` 设到 3 机（阈值→0.9 m/s）。**注意**：调用必须传 `ParamValue(integer=0, real=2.0)` 消息对象，传 dict 会 AttributeError 崩溃。

## 5. 使用方法

### 5.1 一键运行（推荐）

```bash
docker exec -it xtdrone-dev-gpu bash /home/dev/XTDrone-single-car/workspace/run_air_intruder_sim.sh
```

可选参数：`--corner CORNER_0|CORNER_1`（默认 CORNER_1=左下角）、`--alt <高度>`（默认 1.33）、`--headless`（不弹 GUI）。

脚本自动串起：清理残留 → `launch_air_intruder_sim.sh` 启动 multi_vehicle.launch（iris_2 固定左下角出生）→ 等 `/gazebo/model_states` → 起 get_local_pose / ego_swarm_transfer / 3 通信桥 → 等 MAVROS connected → 三机起飞到 1.33m → 起 `air_intruder_pursuit` → 打印监视方法。进程全挂后台，脚本返回后任务自动继续。

### 5.2 手动分步

```bash
# 1) 清理残留 + 启动仿真（选角，默认 fixed CORNER_1）
docker exec -it xtdrone-dev-gpu bash /home/dev/XTDrone-single-car/workspace/launch_air_intruder_sim.sh --gui

# 2) 起 XTDrone 支持栈 + 3 通信桥（容器内）
cd /home/dev/XTDrone-single-car/workspace
python3 /home/dev/XTDrone/sensing/pose_ground_truth/get_local_pose.py iris 3 &
python3 /home/dev/XTDrone/motion_planning/3d/ego_swarm_transfer.py iris 3 &
for id in 0 1 2; do python3 /home/dev/XTDrone/communication/multirotor_communication.py iris $id & done

# 3) 三机起飞（含 MPC_LAND_CRWL 修复）
python3 /workspace/swarm_defense_ws/src/car3_swarm/scripts/uav_offboard_takeoff.py --altitude 1.33 --timeout 120 --no-start-bridge

# 4) 启动围捕节点
source /home/dev/car3_env.sh
roslaunch car3_swarm air_intruder_pursuit.launch
```

### 5.3 结果监视

```bash
# 终态
rostopic echo -n1 /air_intruder/pursuit/result          # CAPTURED / ESCAPED / AIR_INTRUSION_DETECTED
# 状态机推进
grep "state ->" ~/.ros/log/latest/air_intruder_pursuit-*.log | tail
# FSM 实时距离（ENCIRCLED 下的 uav_max / cars_max / hold）
tail -f ~/.ros/log/latest/air_intruder_pursuit-*.log
```

### 5.4 清理仿真（不重开）

```bash
# 容器内
pkill -f '[r]oslaunch px4 multi_vehicle.launch'
pkill -9 -x gzserver gzclient px4 mavros_node ego_planner_node traj_server
pkill -9 -f '[r]osmaster --core'
```

> `[x]` 括号防止 pkill 自匹配误杀自身命令行。gzserver 被强杀后留下的 `<defunct>` 僵尸无害；若整栈已僵死（无 `/gazebo/*` 话题），直接 `docker restart xtdrone-dev-gpu`（workspace 在宿主挂载无损）。

## 6. 关键参数速查（air_intruder_mission.yaml）

| 参数 | 默认 | 含义 |

## 7. 已知边界与注意事项

- **出生角**：仅 CORNER_0（东北角）/ CORNER_1（左下角）可用；当前固定 CORNER_1 验证通过，CORNER_0 为已知薄弱点（iris_0 曾贴墙下降、car1 卡出生点），不推荐复测。
- **入侵方向**：仅支持与出生角相邻的方向（CORNER_1 → DOWN/LEFT）；跨角落直线飞越会提前触发入侵，留待走廊路由 Phase 9。
- **不修改地图**：约束为只改飞行高度；内墙/门数值直接取自 `nesting_room/model.sdf` 实测。
- **改桥后需重启**：`multirotor_communication.py` 改动后 `docker cp` 进容器并重启通信桥。
- **gazebo 僵死**：多次 `kill -9 gzserver` 会污染 gazebo_ros 桥（world 已加载但无 `/gazebo/*` 话题），恢复用 `docker restart xtdrone-dev-gpu`。
