# car3_swarm 一体化任务文档（巡检—入侵—区域封控—捕获/逃逸）

> 本文档覆盖 `multi_car3_mission.launch` 启动的一体化闭环任务：
> PATROL → INTRUSION → CONTAINMENT → CAPTURE / ESCAPE → FINAL_ALIGN → SUCCESS。
> 对应开发文档 2026-08-17 的 Phase 1~10 全部实现与实测结论。

## 1. 快速启动

```bash
# 一键 GUI 演示（宿主终端，推荐）：
# 自动清理残留 → 启动仿真 → 每轮自动跑完整闭环 → 回车复位重开下一轮（仿真不重启）→ q 退出
docker exec -it xtdrone-dev bash /workspace/mission_demo.sh

# 手动方式（容器内，先确保无残留仿真）
source /home/dev/car3_env.sh
roslaunch car3_swarm multi_car3_mission.launch gui:=false   # 无 GUI 跑测试
roslaunch car3_swarm multi_car3_mission.launch              # GUI 演示（Gazebo）

# 任务开始（或由测试探针自动调用）
rosservice call /mission/start "{}"
# 复位重开一轮（Test 9）
rosservice call /mission/reset "{}"
```

- 入侵车 Car E（/car2）在 `fsm/auto_intrude: true` 且 `fsm/wait_patrol_ready: true`
  时，会等两车巡检就绪（到达驻留点）后自动启动入侵，无需外部服务调用。
- 手动触发：`rosservice call /car2/start_intrusion "{}"`。

## 2. 系统架构

```
mission_manager（任务层，永不直接下运动指令）
  ├─ 订阅：三车 /carN/shared_pose、/mission/current_escape_gate
  ├─ 发布：/mission/state、/mission/entry_gate、/mission/intrusion_event、
  │        /mission/result、/car1|car0/containment_goal
  └─ 服务：/mission/start、/mission/reset

per-car 节点（执行层）
  ├─ /car0、/car1：patrol_node.py（巡检 FSM 不变 + 围捕/FINAL_ALIGN 扩展）
  ├─ /car2：intruder_node.py（入侵 FSM：入场→穿门→主动逃逸）
  └─ 每车：virtual_obstacle_node（他车虚拟盒注入 scan_filtered）

公共：car_state_broadcaster（真值 /carN/shared_pose）、map_server、
     /car2 的 AMCL + nav_to_pose（仅入侵前接近门使用）
```

任务状态机（/mission/state）：

```
M_IDLE → M_PATROL → M_CONTAINMENT_INIT → M_CONTAINMENT_ACTIVE
        ├─(捕获)→ M_CAPTURE_CONFIRMED →(1s 全停)→ M_FINAL_ALIGN → M_SUCCESS
        └─(越界)→ M_FAILED_ESCAPE（合法门） / M_INVALID_ESCAPE（原入侵门）
```

入侵车状态机（/car2/intruder_state）：

```
E_IDLE → E_SELECT_ENTRY → E_APPROACH_ENTRY → E_CROSS_ENTRY → E_CROSSED
       →(入侵事件)→ E_EVASION_ACTIVE → E_ESCAPED / E_CAPTURED
E_CAPTURED / E_CROSSED / E_EVASION_ACTIVE →(reset)→ E_RETURN_OUT
       →(在内区先经最近门驶出，再沿外圈回出生点)→ E_IDLE
```

## 3. 关键机制

| 机制 | 实现 |
|---|---|
| 入侵判定 | outside→inside 持续 `fsm/intrusion_debounce`；entry_gate = 穿点最近门；多轮模式下需本轮先观察到 E 在外侧（e_seen_outside 门闩，reset 清空，防止上一轮捕获后 E 仍在内区被误判入侵） |
| 入口选门 | `entry_mode=fixed` 固定 `entry_gate`；`random` 每轮随机换门（排除上一轮入口，持久 RNG：`random_seed>0` 序列可复现用于测试，`0`=时间种子真随机用于演示）；接近路径带走廊中转点（`approach_waypoints`），回归段同样带中转点（`return_waypoints`，按驶出/最近门选取），防全局规划两段都抄近路穿内区；回归完成以到达出生点邻域为准（`spawn_arrive_dist`，出生点距北墙 0.4m 在墙斥力半径内，move_base 末段引力-斥力平衡会悬挂）；manager 侧保险：E_RETURN_OUT 期间穿内区不计入侵；复位后 E 先回归出生点再开始新一轮（`spawn_return_dist` 触发，出生点由 launch 的 car2_x/y 注入） |
| 多轮复位 | reset 后 E 若仍在内区（上一轮被捕获处），自动经最近门驶出门外（E_RETURN_OUT，move_base）；己方 srv_start 时若离出生点 >0.3m，先 RETURN_HOME（原地转向→直线驶回出生点，激光止停防撞→对齐出生航向）再执行原巡检 FSM |
| 巡检中断 | patrol FSM 任意子状态收到 M_CONTAINMENT_* 立即切 CONTAINMENT_INIT（不重写巡检 FSM） |
| yaw 锁定 | 围捕期三车 angular.z ≡ 0（命令层硬约束）；实测 yaw 漂移 ≤0.10 rad（纯物理滑移） |
| 逃逸选门 | J = wd·Jd + wp·Jp + wo·Jo（距离/追捕者/封堵度），换门需 ΔJ>margin 持续 T_switch（滞回防抖） |
| V 型封堵 | e=(p_G−p_E)/‖·‖，PL/PR = p_E + d_f·e ± d_s·n，角色分配一次锁定（C1/C2 argmin），每 tick 重发 |
| 捕获判定 | d(A,E)≤R_c 且 d(B,E)≤R_c 且 z_A·z_B<0（逃逸轴两侧）持续 T_hold → 全停 |
| 逃逸判定 | E 出内区持续 `fsm/escape_debounce`；穿点最近门==entry_gate → INVALID_ESCAPE |
| FINAL_ALIGN | 全停 `fsm/final_align_delay` 后 A/B 原地旋转面向 E（仅 ω=±final_align_max_omega），|Δψ|<ε_ψ → SUCCESS，超时亦 SUCCESS |
| 虚拟避碰 | 己方-己方 friendly_box [0.45,0.38]，己方-入侵 target_safe_box [0.34,0.30]（允许贴近 R_c 捕获圆） |
| 速度公平 | E 0.35 vs 己方 0.60 m/s（己方略快；参数独立可调，倾向捕获成功） |

参数全部位于 `config/mission_params.yaml`（单点真源，launch 以 rosparam 装载到 /mission 命名空间）。

- 全链路：CONFIRMED 47.40 → FINAL_ALIGN 48.45（全停保持 1.05s≈参数 1.0s）→ SUCCESS 50.90（2.45s）

- result=CAPTURE；无回归（yaw 锁漂移 0.055~0.099 rad，捕获保持 0.45s，无越界事件）
