# car3_swarm 使用文档：三车入侵与围捕仿真

> 适用环境：`xtdrone-dev` 容器 + `/workspace/swarm_defense_ws`（catkin 工作区）。
> 所有命令均在**宿主终端**执行，通过 `docker exec` 进入容器。

## 1. 环境准备

```bash
# 确认容器在运行
docker ps | grep xtdrone-dev

# 确认无残留仿真进程（重要！残留会导致 spawn 冲突）
docker exec xtdrone-dev bash -c 'ps -eo pid,stat,cmd | grep -E "gzserver|rosmaster|roslaunch" | grep -v grep | grep -v defunct'
# 无输出 = 干净
```

容器内每次启动 ROS 前需 source 环境（`/home/dev/car3_env.sh`，已包含 ROS + catkin devel + 本工作区）。

## 2. 快速开始：GUI 演示（推荐，屏幕直看全流程）

一条命令启动带界面的完整导航仿真（Gazebo 左侧 + RViz 右侧，直接显示在宿主桌面）：

```bash
# 终端 1：启动仿真（Gazebo 窗口 + RViz 多车视图自动弹出）
docker exec -d xtdrone-dev bash -c 'source /home/dev/car3_env.sh && export DISPLAY=:1 && exec roslaunch car3_swarm multi_car3_nav.launch gui:=true > /tmp/gui_nav.log 2>&1'

# 等就绪（约 30~60s）：确认 9 个 move_base 话题 + 3 路注入扫描出现
docker exec xtdrone-dev bash -c 'source /home/dev/car3_env.sh && timeout 3 rostopic list | grep -cE "^/car[0-2]/move_base/goal"; timeout 3 rostopic list | grep -cE "^/car[0-2]/scan_filtered"'
# 输出 3 和 3 即就绪

# 终端 2：启动 RViz 多车视图（地图 + 三车 TF + 三色扫描点云，可直接观察虚拟障碍物注入）
docker exec -d xtdrone-dev bash -c 'source /home/dev/car3_env.sh && export DISPLAY=:1 && exec rosrun rviz rviz -d /workspace/swarm_defense_ws/src/car3_swarm/config/multi_car3.rviz > /tmp/rviz_gui.log 2>&1'

# 终端 3：依次启动三车导航脚本（入侵车先动，围捕车 6s 后出动）
docker exec -d xtdrone-dev bash -c 'source /home/dev/car3_env.sh && exec python3 /workspace/swarm_defense_ws/src/car3_swarm/scripts/waypoints_car2.py > /tmp/wp_car2.log 2>&1'
docker exec -d xtdrone-dev bash -c 'source /home/dev/car3_env.sh && sleep 6 && exec python3 /workspace/swarm_defense_ws/src/car3_swarm/scripts/waypoints_car0.py > /tmp/wp_car0.log 2>&1'
docker exec -d xtdrone-dev bash -c 'source /home/dev/car3_env.sh && sleep 6 && exec python3 /workspace/swarm_defense_ws/src/car3_swarm/scripts/waypoints_car1.py > /tmp/wp_car1.log 2>&1'
```

RViz 说明：红/蓝/绿三色点云分别是 car0/car1/car2 的**注入后扫描**（`scan_filtered`）——
某车扫到另一辆车时，点云会在该车车体位置截断，这正是虚拟障碍物在起作用。

## 3. V1 键盘控制（三终端各控制一辆车）

```bash
# 终端 1：启动世界 + 三车（无导航）
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && roslaunch car3_swarm multi_car3_bringup.launch gui:=true'

# 终端 2/3/4：三辆车各自独立的键盘控制
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm keyboard_car0.py'
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm keyboard_car1.py'
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm keyboard_car2.py'
```

键位（在各自键盘终端里按键）：

| 键 | 功能 | 键 | 功能 |
|---|---|---|---|
| w / s | 前进 / 后退 | a / d | 左移 / 右移 |
| q / e | 逆时针 / 顺时针旋转 | 空格 | 急停 |
| + / - | 线速度档位 ±0.1 m/s | ] / [ | 角速度档位 ±0.1 rad/s |
| t | 打印键位帮助 | Ctrl+C | 退出 |

注意：三车之间**没有物理碰撞**（虚拟障碍物方案），键盘驾驶时可能视觉上"穿车"，属预期行为。

## 4. V2 多点导航（依次执行导航点，不会覆盖）

### 4.1 启动

```bash
# 终端 1：启动完整导航栈（无 GUI 时去掉 gui:=true）
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && roslaunch car3_swarm multi_car3_nav.launch gui:=true'

# 终端 2：入侵车（先动）
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm waypoints_car2.py'
# 终端 3/4：两辆围捕车（与入侵车同步即可，各脚本独立）
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm waypoints_car0.py'
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm waypoints_car1.py'
```

每辆车**依次**执行自己的导航点：每个点 `send_goal → 等终态（SUCCEEDED/ABORTED）→ 再发下一点`，
绝不会同时存在两个目标。全部完成后日志打印"全部导航点执行完毕"。

### 4.2 修改导航点

编辑对应入口脚本的 `WAYPOINTS` 列表即可，格式 `(x, y, yaw_弧度)`，单位 m：

```bash
docker exec -it xtdrone-dev bash -c 'vim /workspace/swarm_defense_ws/src/car3_swarm/scripts/waypoints_car2.py'
```

默认路径（围捕场景）：

| 车 | 路径 |
|---|---|
| car2 入侵车 | NW 外墙角 (-6.5,6.6) → 北走廊东行 (0,6.0) → 穿北门 (0,1.8) → 内房间中心 (0,0.8)，全程车头朝南 |
| car0 围捕车 | NE 内墙角 (2.3,2.4) → (1.2,1.2) → 北门内侧东翼 (0.6,0.4)，车头朝北 |
| car1 围捕车 | SW 内墙角 (-2.3,-2.4) → (-1.2,-1.2) → 北门内侧西翼 (-0.6,0.4)，车头朝北 |

**重要约束：任意导航点必须与其他车保持 >0.6m 距离**（repulse_range 保护域），
否则目标落在他车排斥场内会形成绕目标极限环、永不到达（实测现象，属设计预期）。

## 5. 话题接口速查

每车命名空间 `/carN`（N=0,1,2），公共资源不带前缀：

| 话题 | 类型 | 用途 |
|---|---|---|
| `/carN/cmd_vel` | Twist | 运动指令入口（键盘/导航共用） |
| `/carN/odom` | Odometry | gazebo 真值里程计 |
| `/carN/scan` | LaserScan | 真雷达（1440 点 360°，20m） |
| `/carN/scan_filtered` | LaserScan | 注入虚拟障碍物后（nav 使用） |
| `/carN/amcl_pose` | PoseWithCovarianceStamped | AMCL 定位 |
| `/carN/shared_pose` | Odometry | 位置共享（20Hz，三车互相可见） |
| `/carN/move_base` | MoveBaseAction | 导航动作接口（脚本用） |
| `/map` `/static_map` | — | 全局唯一地图，全车共享 |

常用检查命令（容器内）：

```bash
source /home/dev/car3_env.sh
rostopic hz /car0/scan                          # 雷达是否出数据（正常 ~15Hz）
rostopic echo -n1 /car2/shared_pose             # 看某车位置/朝向/速度
rostopic echo -n1 /car0/amcl_pose               # 看 AMCL 定位是否收敛
rostopic list | grep car0 | head -n 20          # 某车全部话题
rostopic echo -n1 /car0/scan_filtered           # 看虚拟障碍物注入效果
```

## 7. 关闭仿真

**重要：必须用下面的方式关闭，把整个仿真链清干净**（直接 Ctrl+C 只关 roslaunch，
gzserver 可能残留，下次启动会 spawn 冲突）：

```bash
docker exec -i xtdrone-dev bash -s <<'EOF'
pkill -f "multi_car3_nav[.]launch"
pkill -f "gzclien[t] -g"
pkill -f "gzserve[r] -e ode"
pkill -f "rosmaste[r] --core"
pkill -f "rviz -[d]"
pkill -f "waypoints_ca[r]"
pkill -f "keyboard_ca[r]"
sleep 3
ps -eo pid,stat,cmd | grep -E "gzserver|gzclient|rosmaster|roslaunch|rviz" | grep -v grep | grep -v defunct
EOF
# 最后一条命令无输出 = 已全部关闭
```

注意 pkill 模式里的 `[x]` 括号写法是**必须的**——它让模式不匹配自己所在的命令行，
否则 pkill 会连自己一起杀掉。

## 8. 故障排查

| 现象 | 排查 |
|---|---|
| 启动后没有雷达数据 | `rostopic hz /car0/scan` 无输出：等 30~60s（nav 节点有 scan 等待前缀）；仍无则关闭仿真重开。**勿看日志里 "Starting Laser Plugin" 行数判断**（rosout 会丢行，以话题数据为准） |
| AMCL 不收敛 | `rostopic echo /car0/amcl_pose` 看是否稳定在出生点附近；初始位姿来自 launch 参数，改过出生位姿需同步改 `carN_x/y/yaw` |
| 某车绕目标转圈不 settle | 目标点落在其他车 0.6m 排斥场内 → 把导航点移远一点 |
| 启动时报 "entity already exists" | 有残留仿真进程 → 按 §7 清理后重启 |
| 键盘不动车 | 确认键盘终端前台运行、焦点在该终端；`rostopic echo /carN/cmd_vel` 看有无指令 |
| RViz 窗口不显示 | 确认 `DISPLAY=:1`；`xdpyinfo -display :1` 检查 X 可达 |

## 9. 修改出生位姿

三车出生位姿是 launch 参数（默认值固定，每次运行一致）。临时改一次：

```bash
roslaunch car3_swarm multi_car3_nav.launch car2_x:=-6.5 car2_y:=-6.5 car2_yaw:=1.5708
```

永久修改：编辑 `launch/multi_car3_nav.launch` 和 `multi_car3_bringup.launch` 顶部的默认值
（两个文件都要改，nav 会把参数透传给 bringup）。
