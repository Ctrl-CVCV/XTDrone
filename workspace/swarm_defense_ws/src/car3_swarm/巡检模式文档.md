# car3_swarm 巡检模式文档

> 内房间双车交叉巡检：两辆麦轮车从对角墙角出发，前出 2m 建立驻留点后原地旋转，
> 以交叉监视方式周期扫描四扇门。本文档说明巡检策略与启动方法。

## 1. 场景与角色

内房间为约 5.95m × 5.95m 的方形封闭空间，四面墙中央各有一扇 1.2m 宽的门：

| 门 | 位置（map 坐标，房间中心为原点） |
|---|---|
| 上门 | (0, 2.975) |
| 右门 | (2.975, 0) |
| 下门 | (0, -2.975) |
| 左门 | (-2.975, 0) |

两车对角初始部署（俯视视角）：

| 车 | 角色 | 出生点 | 出生朝向 |
|---|---|---|---|
| car1 | Car A（左下区域） | (-2.3, -2.4) | 0.808 rad（对准房间中心） |
| car0 | Car B（右上区域） | (2.3, 2.4) | -2.334 rad（对准房间中心） |

## 2. 巡检策略

### 2.1 前出建立驻留点

收到 `start_patrol` 后，车辆沿**当前车体正前方**直线前进 2.0m：

- 前进距离用 **odometry 闭环**计算：巡检开始时记录初始位置 P₀，实时计算
  当前位置与 P₀ 的欧氏距离，累计位移 ≥ 2.0m 即停止全部平移运动，
  不做"固定速度 × 固定时间"的开环估计；
- 前进过程中保持初始航向（P 控制器锁 yaw，防止麦轮不对称导致的航向漂移）；
- 停止后的位置即为该车的**巡检驻留点**，此后 (x, y) 坐标保持不变，
  仅通过 `angular.z` 原地旋转。

### 2.2 交叉监视分配

两车各自监视**对侧较远**的两扇门，形成四门互补覆盖：

| 车 | 负责的门 | 扫描区间 |
|---|---|---|
| Car A（car1，左下） | 上门 → 右门 | 上门 ↔ 右门 周期往返 |
| Car B（car0，右上） | 下门 → 左门 | 下门 ↔ 左门 周期往返 |

### 2.3 目标航向角动态计算

**不硬编码 yaw 值**。车辆完成 2m 前出后，根据实际驻留点 P=(x,y) 与门中心
D=(x_d, y_d) 动态计算目标航向角：

```
θ_d = atan2(y_d − y, x_d − x)
```

驻留点改变（如换出生点参数）后角度自动重算，无需改任何代码。

### 2.4 最短角区间往返扫描

- 两目标角之间取**最短角区间**往返：扫描方向 = sign(normalize(θ₂−θ₁))，
  反向扫回时取反；
- 所有航向误差统一归一化到 **[−π, π]**，正确处理 ±π 环绕边界
  （实测：左门方位 3.037 rad 的场合，正确走 112° 最短弧，
  而不是反向旋转 249°）；
- 到达端点的判据：|yaw 误差| ≤ 0.052 rad（约 3°），进入即认为已面向该门；
- 到达每个端点后**静止观察 0.4s** 再反向扫描，避免边界处瞬间反向的机械感；
- 扫描期 `linear.x = 0`、`linear.y = 0` 严格保持，仅 `angular.z` 非零；
- 扫描角速度默认 0.50 rad/s（明显而不过快的视觉巡检效果）。

### 2.5 错相策略

两车扫描不同相：Car A 先面向**上门**，Car B 先面向**下门**，随后各自往返。
不同入口的被观察时刻错开，观察时间更均匀，双车协同视觉更自然。

## 3. 状态机

```
IDLE ──start_patrol──▶ MOVE_FORWARD ──前进 2.0m──▶ COMPUTE_PATROL_ANGLES
                                                       │ 计算 θ₁, θ₂, 扫描方向
                                                       ▼
IDLE ◀──stop_patrol（任意状态）── ALIGN_FIRST_DOOR ──对准 θ₁──▶ DWELL(0.4s)
   ▲                                                            │
   └────────────────────── 无限循环 ◀───────────────────────────┤
        SWEEP_TO_FIRST_DOOR ◀─对准 θ₁─ DWELL(0.4s) ◀─对准 θ₂─ SWEEP_TO_SECOND_DOOR
```

| 状态 | 行为 |
|---|---|
| IDLE | 零速待命，等 start_patrol |
| MOVE_FORWARD | 直线前进，odom 距离 ≥ forward_distance 停止，yaw 锁定 |
| COMPUTE_PATROL_ANGLES | 按驻留点计算两门方位角与最短扫描方向 |
| ALIGN_FIRST_DOOR | 原地旋转对准第一扇门（最短方向） |
| DWELL | 零速静止观察 dwell_time 秒 |
| SWEEP_TO_SECOND_DOOR | 沿最短区间扫向第二扇门 |
| SWEEP_TO_FIRST_DOOR | 沿最短区间扫回第一扇门 |

`stop_patrol` 在**任何状态**下均立即将全部速度指令置零并返回 IDLE；
之后再次 `start_patrol` 会以当前位置为新 P₀ 重新完整执行巡检流程
（已实测：停后重启前进 2.03m、角度按新驻留点重算）。

## 4. 接口

每车命名空间 `/carN` 下：

| 接口 | 类型 | 说明 |
|---|---|---|
| `/carN/start_patrol` | std_srvs/Trigger 服务 | 开始巡检（已在巡检中则原样返回） |
| `/carN/stop_patrol` | std_srvs/Trigger 服务 | 停止巡检，速度清零回 IDLE |
| `/carN/patrol_state` | std_msgs/String（latch） | 当前状态机状态，供监控/调试 |
| `/carN/cmd_vel` | Twist（发布） | 巡检输出的运动指令 |
| `/carN/odom` | Odometry（订阅） | 闭环距离与航向的来源 |

## 5. 启动方法

### 5.1 启动仿真

```bash
# 启动世界 + 两车 + 巡检节点（默认 gui:=true，Gazebo 直接显示在屏幕上）
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && roslaunch car3_swarm multi_car3_patrol.launch'
```

headless 跑法：`gui:=false`。

### 5.2 开始 / 停止巡检

```bash
# 另开终端，一键控制两车（Car A 先启动）
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm patrol_ctl.py start'
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosrun car3_swarm patrol_ctl.py stop'
```

也可直接调单车的服务（例如只让一辆车巡检）：

```bash
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosservice call /car1/start_patrol "{}"'
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rosservice call /car0/stop_patrol "{}"'
```

### 5.3 观察状态

```bash
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rostopic echo /car0/patrol_state'
docker exec -it xtdrone-dev bash -c 'source /home/dev/car3_env.sh && rostopic echo /car1/odom'
```

## 6. 参数（ROS 参数，均在 launch 文件中）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `doors` | car1: `[[0,2.975],[2.975,0]]`；car0: `[[0,-2.975],[-2.975,0]]` | 门中心坐标 [第一扇, 第二扇]，单位 m |
| `forward_distance` | 2.0 | 前出距离（m） |
| `patrol_speed` | 0.35 | 前出线速度（m/s） |
| `max_omega` | 0.50 | 最大扫描角速度（rad/s） |
| `angle_tolerance` | 0.052 | 到达容差（rad，约 3°） |
| `dwell_time` | 0.4 | 端点静止观察时间（s） |
| `hold_yaw_gain` | 2.0 | 前出阶段航向锁定 P 增益 |
| `rate` | 20.0 | 控制频率（Hz） |

改动方式：编辑 `launch/multi_car3_patrol.launch` 中对应 `<param>`；
换出生点：改 launch 顶部 `carN_x/y/yaw` 参数（门角度会自动按新驻留点重算）。

## 7. 关闭仿真

```bash
docker exec -i xtdrone-dev bash -s <<'EOF'
pkill -f "multi_car3_patro[l]"
pkill -f "gzserve[r] -e ode"
pkill -f "rosmaste[r] --core"
sleep 3
ps -eo pid,stat,cmd | grep -E "gzserver|rosmaster|roslaunch" | grep -v grep | grep -v defunct
EOF
# 最后无输出 = 已全部关闭
```

## 8. 实测验证记录（2026-08-18 headless）

- 前出距离 odom 实测 2.02~2.03m（单 tick 超调，符合闭环判据）；
- 前出全程 yaw 漂移 < 0.0001 rad（航向锁定生效）；
- 驻留点 (-0.90,-0.93) / (0.90,0.94)，与理论直线 2m 位置误差 < 3cm；
- 门方位角实测与理论误差 < 0.01 rad（atan2 动态计算）；
- 扫描期位置漂移 ≤ 0.0005m（平移严格为零）；
- 端点驻留 0.4s（20Hz 采样量化后测得 0.35s）；
- 扫描中 stop_patrol：速度清零、位置完全冻结、回 IDLE；
- 停止后重新 start：从新位置完整重跑（含 ±π 环绕边界最短弧验证）。
